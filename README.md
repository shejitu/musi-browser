# 慕思影视 / 慕思浏览器

一个给电视盒子（遥控器、非触摸）用的轻量影视客户端。
**第 1 页用豆瓣高分榜告诉你"看什么"，第 2 页起用自带片源的影视站解决"在哪播"。**

- 包名 `com.mytv.lite`　minSdk 21（Android 5.0+）　targetSdk 34
- 签名 `app/mytv.jks`（自用证书，v3.x 起可覆盖升级）
- 当前版本 **6.2 / versionCode 46**

---

## 1. 6.2 的首页结构（这一版的核心）

```
第 1 页  🎯 豆瓣高分     ← 打开就是它。只负责"看什么"，不能播
第 2 页  🦊 玄珠         红牛 / 极速 / 量子 / 非凡
第 3 页  🐴 小马         光速 / 电影天堂 / 百度（「索尼」按要求不启用）
第 4 页  🐹 dxawi        暴风 / IK
第 5 页  🎬 影视星球     ysxq.cc，42 万部
第 6 页  ⚡ 飞快         feikuai.in，22 万部
```

**为什么把豆瓣放到第 1 页**

6.0 / 6.1 一打开就是某个影视源的"最新更新"。那是**仓库视角**：一屏 30 部里有一半是没听过的新片，
用户得自己挑；而且同一个源今天有、明天可能就抽风。

豆瓣高分榜是**观众视角**：能上这个榜的片子，海报、评分、口碑都已经被验证过，
一屏就能决定今晚看什么。选片这一步交给豆瓣，比交给任何一个采集站都靠谱。

**豆瓣不能播，为什么还敢放第一页**

因为"不能播"这件事在 6.2 里被藏起来了。点开一张豆瓣海报，面板会立刻弹出（简介、评分、年份都在），
同时在后台拿片名去第 2 页起的那几个源里搜。命中了按钮就直接变成 **「▶ 播放（红牛）」**，
按 OK 进选集。用户的感觉是"豆瓣的海报能直接播"，中间那一步是透明的。

这就是 5.0 做错的地方：5.0 也有豆瓣海报墙，但点进去只能"搜一下试试"，跳到一个空列表让人自己翻。
**发现和播放必须自动衔接，否则豆瓣就只是个不能用的橱窗。**

**顺手填的一个坑：别播错片**

CMS 源的搜索是模糊匹配。实测搜「年会不能停！」，红牛返回的第一条是「年会不能停！2」——
照"取第一条"的写法，用户点《年会不能停》会看到续集。所以 6.2 加了片名相似度打分：

| 分数 | 判定 |
|---|---|
| 100 | 去掉标点空格后完全一致 |
| 85 | 一方包含另一方（「唐人街探案」vs「唐人街探案 合集」） |
| 60 | 只是前缀相同、多出来的是纯数字 / 第N部 / II（续集），**不算命中** |
| 20 | 无关 |

只有 ≥80 才算找到；这个源没有就换下一个源。**宁可靠诉用户"没找到"，也不给用户播错片。**

## 2. 从海报到出画面（6.2 的完整链路）

```
打开 App
  ↓
HomeActivity 默认 tab = 豆瓣高分（DoubanSource，30 部/页，实测能翻到 500 部左右）
  ↓ 遥控器选一张海报，OK
详情面板（秒开：简介 / 评分 / 年份）
  ├─ 同时后台 SourceBook.findPlayable(片名)
  │     └─ 按首页 tab 顺序逐个源 search：红牛 → 极速 → 量子 → … → 飞快
  │        第一个片名对得上的直接采用（前两三个源基本就命中）
  │        → 按钮变成「▶ 播放（红牛）」
  ↓ 按 OK
VodActivity（选集）
  ├─ 按 vod_play_from / vod_play_url 拆分线路
  ├─ m3u8 线路优先排序，默认选中
  └─ 顶部「线路(n)」按钮可手动切
  ↓ 选一集，OK
PlayActivity（只起一个 ExoPlayer，几百毫秒出画面）
  └─ 主线路 onPlayerError → 自动换同集的备用线路，最多试 3 条
```

第 2 页起的影视源不需要这一圈：海报本身就带片源信息，点一下直接进选集，少按两下遥控器。

## 3. 为什么删掉那 6 个站

6.2 移除了：**乌龟影院、思古影视、酷壳影视、乐猪影视、阿里影视、扛把子影院**。

理由很简单：它们已经打不开或者改版到抓不出选集了。留着的结果是用户在电视上点一下、
黑屏等十几秒、退回来看一眼，再点下一个 —— 每一次失败都在消耗信任。

同一个逻辑也适用于影视源：**只收实测能播的**。现在这 9 个源不是"看着像苹果CMS"就收，
而是真把「选集 → 第一集直链」拉下来验证过能取到 `#EXTM3U`：

| 源 | 首组线路 | 前 3 集直链 |
|---|---|---|
| 红牛 hnm3u8 | 玄珠仓 | 3/3 |
| 光速 gsm3u8 | 小马仓 | 3/3 |
| 暴风 bfzym3u8 | dxawi 仓 | 3/3 |
| 影视星球 ysxq | 自带接口 | 3/3 |
| IK ikm3u8 | dxawi 仓 | 2/3 |
| 飞快 feikuai | 自带接口 | 首组是网页地址，换线路可播 |

（2026-10-24 实测。源站会变，这份表也会过期，所以第一页永远放豆瓣 —— 豆瓣不会跑。）

## 4. "轻量播放"到底轻在哪

6.1 之前点了选集会跳主界面播：那等于进浏览器模式，要建 WebView、还要在主线程拉站点配置，
电视上的表现就是长时间黑屏。6.2 的 `PlayActivity` 只做一件事：

```
new ExoPlayer → setMediaItem(直链) → prepare → play
```

没有 WebView、没有嗅探、没有站点配置。另外两条硬规则写在代码里：

1. **只喂直链**。苹果CMS 的 `vod_play_url` 是 `$$$` 分隔的多条线路，第一组经常是云播**网页**
   （`hn.bfvvs.com/play/xxx` 这种），播放器拿到 HTML 必失败。现在按线路拆开、m3u8 排前面。
2. **失败自动换线**。主线路放不出来时，拿同集的备用线路再试，最多 3 条，用户不用退出去手动切。

## 5. 遥控器怎么用

| 场景 | 按键 |
|---|---|
| 首页 | ▲▼◀▶ 选片，OK 打开；顶部 tab 换页 |
| 详情面板 | OK = 播放（豆瓣条目会自动找源），返回 = 收起 |
| 选集 | ◀▶ 挑线路，方向键选集，OK 播放 |
| 播放中 | OK 显示进度条，返回 = 回选集；菜单键切铺满/完整 |
| 浏览器 | 顶栏【📁 站点】或菜单键 = 开关站点面板；返回 = 上一页 |
| 网页 → TV 界面 | 顶栏【⚡轻站】 |
| 轻站面板 | 方向键选集，OK 播放，返回 = 回网页 |

首次打开会有一层一次性指引，按 OK 即消失，之后不再打扰。

## 6. 轻站（把网页变成电视界面）

浏览器里打开任意影视网页，按【⚡轻站】，把当前页结构化成 `标题 + 海报 + 选集网格`，
落成原生 TV 界面。三级降级，任何一级失败都不会让功能变成"不可用"：

```
① 站点规则（assets/lite_rules.json，或用户自己导入的 JSON）
      selector 精确抓选集；可选 js 片段处理特殊站
   ↓ 没匹配到
② 通用嗅探：<video>/<source>、全页正则扫 m3u8/mp4/flv、收集 iframe、复用网络嗅探
   ↓ 还没有可播地址
③ 逐集解析：点某一集 → 隐藏 WebView 打开该集页 → 嗅探 m3u8/mp4 → 命中即播
```

不用 Rhino / 不用 JS 引擎的原因很直接：脚本本来就该跑在页面里。
WebView 自己就是 JS 引擎，还额外拥有已渲染的 DOM、已登录的 Cookie、真实的 `location`。
`evaluateJavascript` 一行注入就能完成 OK浏览器 那套"远端下发脚本 + Rhino 执行"要做的事。

规则格式：

```json
{
  "rules": [
    {
      "id": "example",
      "name": "示例站",
      "hosts": ["example.com"],
      "selector": "a[href*='/vodplay/'], .playlist a",
      "js": "return {items: [...document.querySelectorAll('.episode a')].map(a=>({name:a.textContent,url:a.href}))}"
    }
  ]
}
```

`hosts` 按域名后缀取最长命中；`selector` 抓不到会自动回退通用嗅探，写错不会把功能写死。
维护入口：设置 →「⚡ 轻站规则管理」→ 粘贴 JSON 网址，或点「拉取官方规则」。
**站点改版不需要重新发版。**

## 7. 功能清单

| 模块 | 能力 |
|---|---|
| 首页海报墙 | 豆瓣高分榜（第 1 页）+ 5 组影视源，5 列竖版海报，可翻页 |

| 网页浏览 | 任意网址 / Bing 搜索，边翻页边嗅探 m3u8/mp4/flv |
| 轻站 | 网页一键转 TV 界面，三级降级 |
| 仓库管理 | TVBox 单仓/多仓配置，站点直进海报墙或浏览器 |
| 本地文件 | 播放 `Download/download` 里的视频、安装 APK |
| 局域网控制 | 手机打开 `http://电视IP:8080` 推送网址 / 代理 / 文件 |

| 更新检查 | 启动时查 GitHub 最新 release，有新版才提示，查不到保持原样 |

## 8. 构建与发布

云端（推荐）：push 到 `master` 触发 `.github/workflows/build.yml`，
JDK 17 + Android SDK 34 + Gradle 8.5 → `assembleRelease` → 签名 → 产物进 artifact 与 `apk` 分支。

```bash
gradle assembleRelease          # 本地需要 JDK17 + platform-34
# 产物 app/build/outputs/apk/release/app-release.apk
```

⚠️ **签名密钥是公开的**：`app/mytv.jks` 与密码写在 `app/build.gradle` 里，而仓库是公开的。
好处是任何一次构建都能覆盖升级，坏处是任何人都能签出「同签名」的包。
要收紧就改成 base64 存 Secrets、从仓库删 jks —— 但新包与旧包签名不同，必须卸载重装一次。
当前为保持升级连续性，暂不切换。

## 10. 已知限制（诚实清单）

- 豆瓣只提供片名和评分，**片源来自第三方采集站**，新片可能还没被收录；找不到时会明确提示，不会播错片；
- 豆瓣接口没有官方承诺，改版/限流都可能让它失效 —— 界面会退到"先看第 2 页起的影视源"，不影响播放；
- 采集站经常换域名、换线路，**m3u8 直链今天通不代表明天通**，播不了时先在选集里切「线路」；
- 部分站点播放器在 iframe 里且需要点击/验证，逐集解析可能超时；
- DRM（Widevine）加密源无法播放；
- TVBox Spider（type 3，dex/js 爬虫）源不内置引擎，会转网页嗅探；
- 海报墙只支持苹果 CMS V10 协议；
- WebView 代理在系统 WebView 过旧的设备上可能不生效（失败静默降级）。

## 11. 合规

本项目**不内置、不分发任何影视内容，也不内置任何破解/解密引擎**。
豆瓣数据来自其公开只读接口；影视源来自用户可自行配置的公开采集接口；
轻站只是把「用户自己在浏览器里打开的网页」重新排版成适合遥控器的界面。
请在有合法授权的前提下使用。
